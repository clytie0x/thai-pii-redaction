# PDPA coverage and lifecycle: alternatives and experiment design

Research date: 2026-10-31. Scope: local research design and assessment, not a production detector replacement, legal opinion, compliance certificate, or live governance integration. No model weights were downloaded, packages installed, private text uploaded, or old held-out data opened for these notes. Existing source was read statically; no inference timings or accuracy results were measured.

## Which existing alternatives should be reused, and what gap remains?

### Takeaway

Reuse the current Thai detector for identity spans, established recognizer/model interfaces for comparison, and existing privacy-workflow designs for governance. The justified additional work is a small, attribution-aware assessment layer that distinguishes a sensitive topic from information about a person and records uncertainty; an NER label or embedding similarity cannot establish consent, lawful processing, or completion of a rights request.

### Cited Findings

- **Observed project baseline:** `report.py` contains eight category keyword expressions, returns the first match per category, and explicitly treats Section 26 findings as flag-only. `analyze_text` additionally tries the optional semantic module, de-duplicates by category, and catches all semantic exceptions. `sensitive_detector.py` uses multilingual MiniLM, Thai sentence splitting, maximum cosine similarity to prototypes, a default 0.55 threshold, and a single highest-scoring category per sentence. It has no subject-attribution decision. These are source observations, not runtime evidence. Sources: [current report source](../../../../pii_redactor/report.py), [current semantic source](../../../../pii_redactor/sensitive_detector.py), [ML extras](../../../../requirements-ml.txt). The relative links are for repository navigation; inspect the current files when implementing.
- **Presidio:** a reusable local analyzer framework combines recognizers and NLP engines; its documented context mechanism increases confidence when nearby context words occur and permits custom enhancement. Supporting a language requires both an appropriate NLP engine and adapted recognizers. This is useful architecture and a comparator, but a nearby-word score increase is not person-to-sensitive-attribute relation resolution. Sources: [analyzer](https://presidio.dataprivacystack.org/analyzer/), [context enhancement](https://presidio.dataprivacystack.org/tutorial/06_context/), [language adaptation](https://presidio.dataprivacystack.org/tutorial/05_languages/).
- **Presidio provenance:** the official repository is now `data-privacy-stack/presidio`; the old Microsoft documentation redirects. The current code license is MIT. Preserve current source URLs rather than assuming Microsoft ownership remains current. Sources: [transition notice](https://github.com/data-privacy-stack/presidio/blob/main/docs/project_transition.md), [license](https://github.com/data-privacy-stack/presidio/blob/main/LICENSE).
- **GLiNER:** the framework supports label-conditioned span extraction; the `urchade/gliner_multi-v2.1` card provides `predict_entities(text, labels)`, lists multilingual support, 209M parameters and Apache-2.0. Older model families have different licenses, including noncommercial variants, so a library license alone does not license every weight. This is a real local NER alternative, not evidence of Thai PDPA attribution quality. Sources: [official framework](https://github.com/urchade/GLiNER), [specific multilingual model card](https://huggingface.co/urchade/gliner_multi-v2.1).
- **PII Engineer:** the official Rust/ONNX project lists Thai as a secondary language and nine identity-oriented output types. The linked model card advertises GLiNER2/mDeBERTa-v3-base, approximately 620 MB of models and Apache-2.0, but its headline says 30+ types while its actual type list has nine. Treat the advertised Thai F1 and CPU latency as unreplicated author claims, not comparable evidence for this project. Sources: [repository](https://github.com/gantz-ai/pii.engineer), [linked weight card](https://huggingface.co/pii-engineer/PII-Engineer-Multi-NER-v2.1).
- **Presidio evaluation tooling:** `presidio-research` supplies template-based fake PII generation, span/tag representations, entity mapping, and precision/recall/error analysis. Its bundled fake-identity assets carry a separate attribution/share-alike notice, so use its methodology or independently authored synthetic values rather than blindly copying its dataset. Source: [official evaluator repository](https://github.com/data-privacy-stack/presidio-research).
- **SDV/SDMetrics:** SDV generates synthetic tabular data; SDMetrics privacy metrics assess disclosures and closeness between real and synthetic tables. These address synthetic-data privacy and utility, not Thai text-span detection or subject attribution. Use only if a later study actually synthesizes tables; synthetic narrative templates need their own detection labels. Sources: [SDV documentation](https://docs.sdv.dev/sdv), [SDMetrics privacy metrics](https://docs.sdv.dev/sdmetrics/data-metrics/privacy).

### Inferences

- A rewrite of identity detection is unjustified before a same-data comparison. Keep CRF/regex output fixed across experiments and add an assessment object with `category`, input `evidence_span`, `subject_link`, `assertion_status`, `attribution_state`, `review_reason`, `method`, and `coverage_status`. A topic hit may be useful even when personal attribution is unknown.
- Proposed attribution states are `person_attributed`, `topic_only`, `uncertain`, and `not_assessed`. These are research labels, not legal determinations. `person_attributed` should require evidence of a subject and an attribute relation, with explicit or indirect identification recorded separately. First person may refer to the speaker without naming them; absence of a NAME span does not prove non-personal data.
- Keep negation, historical/current status, hypothetical wording and quotation as separate assertion features. A negative medical test result or a quotation about an identifiable person can still convey personal information. Do not remove these findings merely because they contain negation or quote marks.
- Concrete discriminators for fresh synthetic cases: a general article on diabetes versus a named person's treatment; a political party's office address versus a person's expressed support; discussion of face-recognition technology versus a template used to identify a person; fictional dialogue versus a record concerning an indirectly identifiable person. Ambiguous cases should enter review rather than be forced into false certainty.
- Detection, personal attribution, uncertain review and enforcement must remain four separate outputs. Section 26 assessment findings stay warn/report signals under the repository boundary. Existing outbound PII enforcement continues through the existing core; a research classification must not silently turn into blocking, masking or authorization.

### Gaps

- No retrieved alternative demonstrates complete Thai PDPA category coverage plus person attribution, negation, coreference and lifecycle fulfillment on an independent Thai dataset. This is a bounded evidence gap, not proof that no such product exists.
- No local model or external comparator was installed/run. GLiNER is an optional future comparator. PII Engineer's compatibility, exact artifact inventory, pinned revision, attribution behavior and claimed benchmarks require source-level and same-dataset validation before adoption. Its README auto-downloads models on first run, so do not start the service in an offline-only assessment accidentally.
- The eight current labels are an implementation inventory, not the legal taxonomy. The legal-source workstream must define the full category IDs and boundary cases; unsupported categories, including raw modalities, must be represented explicitly rather than inferred from model marketing.

## Which three experiments are implementable, fair and affordable locally?

### Takeaway

Run three actual methods on a new synthetic, grouped dataset: frozen keyword baseline, attribution-aware rules with existing NER, and the same context layer with a real pinned multilingual embedding adapter. The third experiment is conditional on already available local weights or a separately authorized future fetch; a fake vector or keyword proxy must never be reported as a model run.

### Cited Findings

- **Real candidate capability:** `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` is a sentence-similarity embedding model with 384-dimensional vectors and a documented 128-token sequence limit. Its model card states Apache-2.0; it does not expose a native PDPA classifier, subject resolver, consent verifier or calibrated legal confidence. Source: [specific model card](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2).
- **Source fingerprint observed on the research date:** Hugging Face metadata reports revision `e8f8c211226b894fcb81acc59f3b34ba3efd5f42`, Thai (`th`) language metadata, and 117,653,760 F32 parameters plus 512 I64 values. The repository offers distinct safetensors, ONNX and OpenVINO artifacts; these are different execution choices and require separate fingerprints. Source: [official metadata API](https://huggingface.co/api/models/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2).
- **Multilingual scope is task-dependent:** Sentence Transformers describes this model as multilingual paraphrase training on parallel data for 50+ languages; its documented semantic-similarity evaluations do not establish Thai PDPA-category or attribution accuracy. Source: [official pretrained-model documentation](https://www.sbert.net/docs/sentence_transformer/pretrained_models.html).

### Inferences

**The three pre-registered strategies below are proposed experiments, not completed results.**

| Strategy | Actual computation | Testable question | Important failure mode |
|---|---|---|---|
| A. Frozen existing keywords plus core | Call current Section 26 keyword scanner with semantic processing explicitly disabled; retain unchanged CRF/regex identity output. Preserve current eight-label mapping as a frozen baseline. | What do existing topic flags cover, and how often do they mistake general discussion for personal information? | Unsupported categories and paraphrases are missed; a topic hit has no attribution claim. |
| B. Context/rule attribution plus core | Match a versioned expanded cue inventory, retain every input span, and resolve bounded subject/attribute relations using existing NER, pronouns, field labels, sentence boundaries and explicit uncertainty rules. No new neural weights. | Does a lightweight context layer improve attribution precision while preserving recall and review visibility? | Missing NER, cross-sentence coreference, multiple people, indirect identifiability and unfamiliar paraphrases. |
| C. Real MiniLM candidate retrieval plus B | Encode short windows using the pinned model and compare against versioned positive and hard-negative Thai/English examples; use per-category development thresholds and a review band, then apply B's attribution logic. Permit multiple category candidates, retaining exact evidence spans. | Does semantic retrieval recover genuinely new paraphrases at an acceptable false-alert/review/CPU cost? | Similarity confuses topic with assertion; negation, long-window truncation and out-of-distribution wording remain difficult. |

- A must not accidentally invoke `analyze_text`'s current implicit semantic pass. Expose `engine_requested` and `engine_effective`; unavailable C yields `not_run`/`unavailable`, never A or B relabeled as C. Keep model load failures distinct from clean-negative outputs.
- For A, report both performance on the shared eight-label subset and full-taxonomy coverage. On a full-label detection task, an absent positive label is a miss; additionally disclose that it is unsupported. Do not reward an unsupported category as a true negative or compare an eight-label macro average directly with a larger-label macro average.
- C is a retrieval-assisted classifier built around embeddings, not a native classification model. Use separate examples for topic-only and person-attributed cases. Similarity values are ranking scores, not calibrated probabilities; do not present 0.55 as 55% certainty. Keep explicit `unknown` review when scores tie, attribution is missing, or the text exceeds assessed scope.
- Optional later local model challenger: pinned `urchade/gliner_multi-v2.1` for label-conditioned sensitive span proposals, or a supervised lightweight classifier trained on fresh development data. This is an additional comparator, not silently part of the three-method evidence. GLiNER output still needs the same attribution/review layer, and a generative local LLM is unnecessary before these lower-cost methods are assessed.

**Dataset and split design:**

- Create a new suite with independently authored synthetic Thai, English and mixed-language documents. Use ordinary identifiers, all agreed Section 26 categories, topic-only negatives, person-attributed positives, uncertainty and unsupported-media examples. Stratify by category and attribution state; include keyword-free paraphrases and hard negatives containing the exact baseline keywords.
- Include first-person disclosures without names, pronouns, shared surnames, multiple people with different attributes, quoted statements, negated facts, old records, allegations, fictional examples, missing context, indirect-identification combinations, tables, OCR-like corruptions and long text. Minors, deceased-person references and special-context scope questions receive separate context labels from the legal taxonomy, not automatic NER assumptions.
- Group template families, paraphrases, document forms and subject/value families into one split. Freeze a manifest with train/development/final-test roles before tuning. Thresholds, cue expansions and prototype edits use only development data. Keep pre-existing frozen/held-out corpora unopened. A post-result repair requires a new evaluation version, not repeated tuning on final test.
- Prefer at least two independent annotators for a final-test subset, a written attribution rubric, adjudication and disagreement rates. Synthetic labels validate designed cases; they do not establish prevalence, transfer to real organizations, or freedom from author/template bias.

**Metrics and acceptance decisions:**

- Report topic-category precision/recall/F1/F2 and macro per-category metrics; span exact match and overlap separately; personal-attribution precision/recall, category-plus-attribution joint correctness, document-level sensitive-person recall and all-scope miss counts. Include counts and confidence intervals, not only percentages.
- Report topic-only false-alert rate, review rate and the recall/precision among automatically assessed cases. Plot risk versus coverage as thresholds change. Do not count uncertain/review outputs as correct positive classifications. Count an undecided positive as unresolved for end-to-end automatic coverage while reporting that review captured it.
- For the ordinary identity detector, verify unchanged outputs and count regression cases separately. A higher Section 26 category score does not compensate for identity leakage. Keep assessments of interpretation, masking and lifecycle decisions in distinct tables.
- Evaluate fail paths: no weights, incompatible model/config, offline loading, timeout, blank input, malformed spans, repeated text, token overflow and unsupported modality. Show `not_assessed` explicitly. An empty result is not equivalent to confirmed absence.
- Compare all methods on the same documents, category mapping, evidence-span conventions and CPU settings. Use paired bootstrap by document/template family for differences if the sample size supports it. Record the number of categories each method can actually emit. Do not import Presidio/PII Engineer headline benchmark scores into this comparison.

**Adapter, source and compute contract:**

- Before a future C run, record model ID, immutable revision above, model-card and license URLs, local weight/config/tokenizer SHA-256 values, package versions, adapter source commit, pooling/normalization, prototype and taxonomy digests, thresholds, split digest, random seed, batch size, thread count, execution backend and device. This turn verified upstream metadata, not local weight identity.
- Load only a declared local artifact path in offline mode when using an existing cache. For a user-approved later fetch, verify source/license and all files before execution; keep remote code disabled. Distinguish dependency importability, verified local artifact presence, successful model load and successful prediction. Current `is_available()` checks only importability and therefore cannot prove these stronger states.
- The supplied machine envelope is CPU with 24 logical threads and 32 GB RAM, without an observed GPU. F32 parameter storage alone is approximately 471 MB decimal, calculated from upstream metadata; tokenizer, runtime, activations, batches and multiple process copies add overhead. This is a lower-bound arithmetic estimate, not measured RSS. Avoid loading one model per request worker.
- No paid API is required. Account for one-time download/storage and cold-load cost, local electricity/time, annotation, version maintenance and support. External API dollar cost is zero in the proposed local run; total operating cost is not zero. Do not reuse a vendor's VPS price as this machine's measured cost.
- First measure cold-load time and peak RSS once; then warm p50/p95 per-document latency, throughput, peak RSS, tokenizer truncation rate and score stability with fixed 1/4/8 thread settings. Bound input windows at the tokenizer level below 128 tokens, preserve global offsets, overlap windows where needed and deduplicate by evidence span/category. Batch only after latency and memory are measured. No latency or model-quality promise is supportable yet.
- Choose B as the candidate default only if fresh measurements support its attribution precision/recall and review burden. Keep C an explicit optional extra unless its measured incremental recall and cost justify adoption. Record tradeoffs; no universal numeric quality target should be invented before dataset size, use risk and review capacity are agreed.

### Gaps

- Weights, cache availability, actual package compatibility, latency, RSS, thresholds and calibration are unverified. No result table should contain fabricated C predictions or zeros that imply an executed negative run.
- A text adapter cannot inspect raw fingerprint/face/voice templates, DNA records, raw audio/video, encrypted files, inaccessible attachments or unidentified archives. A mention of biometrics/genetics is only a text clue. OCR or transcription is a separate extraction dependency with its own error and coordinate/provenance contract.
- No closed category list proves open-world completeness. Unknown identifiers, rare dialects, implicit traits, novel indirect-identification combinations and organizational context remain review/research gaps. Report assessed input scope beside every result.

## How should lifecycle assessment connect to existing governance workflows?

### Takeaway

Model lifecycle obligations as explicit, evidence-linked workflow states and produce recommendations or simulation results. Consent collection, identity verification, retention execution, subject-right fulfillment and deletion receipts require authoritative systems and controller decisions; synthetic context fields cannot establish that those events happened.

### Cited Findings

- **Fides:** its Privacy Center collects access, erasure and consent requests; configuration distinguishes manual approval and subject identity verification. The official repository is archived/read-only since 2026-08-28 and its license is Apache-2.0. Use its concepts as an architectural reference; a maintained replacement or support plan must be checked before a new integration. Sources: [Privacy Center](https://ethyca.github.io/fides/development/ui/privacy_center/), [configuration](https://ethyca.github.io/fides/dev/config/), [repository archive notice](https://github.com/ethyca/fides), [license](https://github.com/ethyca/fides/blob/main/LICENSE).
- **Klaro:** a BSD-3-Clause website consent manager can group third-party apps by purpose and defer their execution according to consent settings. This is a relevant UI/runtime consent alternative for website services, not a general rights or record-retention engine. Source: [official repository](https://github.com/kiprotect/klaro).
- **Open Policy Agent:** OPA separates policy decision-making from enforcement, accepting structured inputs and evaluating policy/data to return decisions. Its own distinction is directly relevant to keeping a simulated lifecycle assessment separate from an executor. Source: [official OPA documentation](https://www.openpolicyagent.org/docs).

### Inferences

- Do not reinvent a complete CMP/DSR platform inside the redactor. Produce a small exportable evidence object or future adapter interface: dataset/system ID, controller/processor role, purpose, data categories, subjects, asserted legal-basis/exception references, source-of-claim, notice/consent receipt reference, recipients/transfers, retention trigger/duration, rights channels, policy version, responsible owner and verification state. Missing values must remain missing; the assessment engine must not guess consent or an exception from prose.
- Use a lifecycle state machine for research: `collect -> assess -> minimize -> authorized_use -> disclose -> retain -> review -> dispose`, with alternate `hold`, `rights_request`, `breach_review` and `unknown` states. These are proposed engineering states, not a claim that the legal workstream has validated every transition. A controller-approved policy and authoritative context decide applicability.
- Return `satisfied_by_evidence`, `missing_evidence`, `needs_review`, `not_applicable_with_reason`, `not_assessed` or `simulation_only` for each obligation. Record the source, owner, timestamp and expiry of evidence. Caller-supplied `consent=true`, retention dates or role fields are assertions; label them `simulation_only` unless checked against the authoritative system.
- Keep recommendations detached from execution: a retention deadline can recommend disposal, but cannot delete files; a rights request can recommend discovery, identity checks and third-party review, but cannot certify fulfillment; a withdrawal scenario can identify affected processing, but cannot claim downstream consent withdrawal occurred. Do not treat policy-engine output as a deletion receipt.
- Preserve the current project's local DSAR locate-only boundary. An expanded rights assessment can link a discovery finding to a proposed request workflow, but locating files is not access delivery, identity verification, erasure, rectification or portability completion. The system of record must supply request identity, authorization, task execution and audit evidence.
- Fresh synthetic lifecycle scenarios should cover unknown basis, expiry with legal hold, withdrawal with remaining processing basis, changed purpose, cross-border recipient unknown, access request with possible third-party content, unverified requester, correction dispute, partial downstream deletion failure and unsupported input. Score obligation applicability, missing-evidence detection, correct abstention and unauthorized-action count separately from detector metrics. These are governance-context simulations only.
- Proposed Thai recommendation: เริ่มทดลองสามวิธีบนชุดข้อมูลสังเคราะห์ใหม่ ได้แก่ keyword เดิม, กฎเชื่อมข้อมูลกับบุคคล และกฎเดิมเสริม MiniLM จริงแบบเลือกเปิด เปรียบเทียบการตรวจหัวข้อกับการระบุว่าเป็นข้อมูลของบุคคลแยกกัน เก็บกรณีกำกวมให้คนทบทวน และรายงานข้อจำกัดของแต่ละหมวด งาน consent การเก็บรักษา และสิทธิของเจ้าของข้อมูลให้เป็นการประเมินหลักฐานหรือจำลองแผนงาน จนกว่าจะเชื่อมระบบที่ยืนยันเหตุการณ์จริงได้

### Gaps

- No real consent records, organizational data inventory, controller policy, identity provider, rights queue, deletion executor, recipient registry or audit trail was connected or tested. No lifecycle obligation can be marked fulfilled from this research alone.
- No maintained full-stack rights/retention tool was validated for Thai organizational deployment in this bounded review. Fides archival is a material adoption risk. Klaro and OPA cover narrower pieces and do not fill that whole gap automatically.
- Final statutory categories, exceptions, retention requirements and rights timing must come from the current Thai primary-law workstream and the organization's actual processing context. The detector assessment is not legal certification.
