AI Guard

หยุดข้อมูลส่วนบุคคลรั่วไหลก่อนถึงมือ AI

เวลาเราวางข้อความลงแชท AI เพื่อขอให้ช่วยร่าง สรุป หรือแปล ข้อความนั้นมักมีเลขบัตรประชาชน ชื่อ เบอร์โทร หรือที่อยู่ติดไปด้วยโดยไม่ทันสังเกต และข้อความที่ส่งออกไปแล้วเรียกคืนไม่ได้ AI Guard ทำงานบนเซิร์ฟเวอร์ของทีม รับข้อความต้นฉบับเพื่อตรวจจับและปกปิดก่อนส่งต่อไปยังโมเดลภาษา แล้วกู้คืนคำตอบภายในคำขอเดียว

คำเตือนจากระบบ

ยังไม่มีข้อมูล
เส้นทางนี้เป็น stateless ข้อความต้นฉบับ การจับคู่ และไฟล์ PDF ถูกใช้ระหว่างคำขอเดียวเท่านั้น โดยงาน PDF/การพักข้อมูลของ proxy ใช้พื้นที่ชั่วคราว แบบหน่วยความจำ (tmpfs) ไม่ใช่ดิสก์ถาวร และถูกทิ้งเมื่อ container หยุดหรือสร้างใหม่ เมื่อคำขอจบ reference ชั่วคราวจะถูกลบแบบ best effort response คืนเฉพาะข้อความผลลัพธ์ จำนวน/ชนิด และสถานะความปลอดภัย ไม่คืน mapping หรือ token-bearing entity projection อย่างไรก็ตาม ข้อความที่ถูกปกปิดแล้ว (โดยเฉพาะโหมดข้อมูลสมมุติที่อ่านเป็นธรรมชาติ) ยังถือเป็นข้อมูลส่วนบุคคลตามกฎหมาย PDPA อยู่ดี เพราะเป็นการทำให้เป็นนามแฝง (pseudonymization) ไม่ใช่การทำให้ไม่สามารถระบุตัวตนได้อย่างถาวร (anonymization) เราไม่กล่าวอ้างเกินกว่าสิ่งที่ระบบทำได้จริง

เครื่องมือเอกสาร

เอกสาร

ใช้งานตรงจากเบราว์เซอร์ ไม่ต้องติดตั้งอะไรเพิ่ม

ทาดำ PDF

อัปโหลดไฟล์ PDF ระบบตรวจจับข้อมูลส่วนบุคคลและสร้างตัวอย่างที่วาดกล่องทึบ รองรับทั้งไฟล์ที่มีชั้นข้อความและเอกสารสแกน (มี OCR ในตัว) ตำแหน่งกล่องยังใช้การจับคู่เชิงประมาณ จึงต้องตรวจทุกหน้าก่อนนำไฟล์ไปใช้

รายงาน PDPA

ออกรายงานความเสี่ยงตาม PDPA เป็นไฟล์ PDF ภาษาไทย จากข้อความในช่อง "ลองของจริง" ด้านบน รายงานมีเฉพาะคะแนน เกรด และจำนวนที่พบตามหมวด ไม่มีข้อความจริงหรือค่าข้อมูลอยู่ในไฟล์

สำหรับนักพัฒนา

ใช้เป็น API และความโปร่งใส

เชื่อมต่อ AI Guard เข้ากับระบบของคุณเองผ่าน REST API ชุดเดียวกับที่หน้านี้ใช้งาน

Endpointคำอธิบายขีดจำกัด
POST /api/v1/detectตรวจจับข้อมูลส่วนบุคคลอย่างเดียว ไม่มี session ไม่มี vaultข้อความ ≤ 20,000 ตัวอักษร
POST /api/v1/guardตรวจสัญญาณ prompt injection ภาษาไทย/อังกฤษ แจ้งเตือนอย่างเดียว ไม่บล็อกข้อความ ≤ 20,000 ตัวอักษร
POST /api/v1/roundtripปกปิด ส่งเข้าโมเดลภาษา แล้วกู้คืน จบในคำขอเดียว แบบ statelessข้อความ ≤ 20,000 ตัวอักษร
POST /api/v1/redact-pdfสร้าง PDF ตัวอย่างพร้อมกล่องทึบแบบประมาณ ต้องตรวจทุกหน้าก่อนใช้PDF ≤ 50MB; หลักฐานปัจจุบันครอบคลุมเอกสารสแกน 1 หน้า
POST /api/v1/analyze-reportออกรายงานความเสี่ยง PDPA เป็นไฟล์ PDFข้อความ ≤ 20,000 ตัวอักษร
GET /api/v1/healthตรวจสถานะบริการไม่มี
POST /api/v1/auth/loginแลก access code เป็น signed HttpOnly cookie อายุ 30 นาทีมี rate limit แยก

หน้าเว็บและ health เปิดอ่านได้ ส่วน business API ต้องมี cookie ที่ได้จาก login อัตราเรียกใช้รวม 10 คำขอต่อวินาที

# ตั้ง AIFT_ACCESS_CODE ใน environment โดยไม่ใส่ค่าจริงใน script
curl -sS -c aift-cookie.txt -X POST https://team08.aiforthai.in.th/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d "{\"access_code\":\"${AIFT_ACCESS_CODE}\"}"

curl -b aift-cookie.txt -X POST https://team08.aiforthai.in.th/api/v1/roundtrip \
  -H "Content-Type: application/json" \
  -d '{
    "text": "เรียนหัวหน้างาน ผมชื่อ นายสมชาย ใจดี ติดต่อกลับได้ที่ 081-234-5678 ครับ",
    "mode": "token",
    "provider": "tokenmind"
  }'
rm -f aift-cookie.txt

นโยบายข้อมูล

ข้อความต้นฉบับวิ่งผ่าน reverse proxy และเซิร์ฟเวอร์ของทีมบนโครงสร้าง NECTEC ก่อนถูกปกปิด ข้อความที่ผ่านการปกปิดแล้วจึงถูกส่งต่อไปยัง thaillm-8b ของ Pathumma การจับคู่ตัวจริงถูกใช้ชั่วคราวภายในคำขอเดียว ไม่ถูกส่งออกเป็น mapping และไม่ได้ตั้งใจเขียนลงดิสก์ log ฝั่งแอปไม่มีเนื้อหาข้อความหรือ query string
