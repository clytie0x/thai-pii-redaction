# YRSS evaluation v2 pre-registration

Date: 2026-11-13. Authorized scope: the owner approved this plan on 2026-11-13.
This record precedes the new corpus, the new harness code, and every detector
change made for this campaign. Version: `yrss-eval-v2`.

It does not reopen, rescore, or rebind gold-v4, blind-v1, sealed blind-v2,
`yrss-holdout-v1`, or the hard-dev and hard-test locks. Their scores keep the
labels in `research/yrss2026/CLAIM-MAP.md`.

## Why a new evaluation

The existing evidence has five weaknesses a judge can find.

1. Four corpora give F2 from 0.799 to 0.965, and the submitted abstract cites
   the development set.
2. The comparison split has 60 documents and 6 entities for most types.
3. STUDENT_ID applies to students only, takes 25 of 252 gold-v4 documents, and
   is the weakest type on sealed blind-v2 (10 of 28).
4. NER-only baselines are scored on types they cannot label, and the only LLM
   baseline is `gemma3:1b`.
5. Every corpus was written by one model family, with no human agreement.

## Entity scheme

Eleven types. DRIVER_LICENSE replaces STUDENT_ID.

| Group | Types |
|---|---|
| Structured | THAI_ID, PHONE, EMAIL, BANK_ACCOUNT, CREDIT_CARD, PASSPORT, VEHICLE_PLATE, DRIVER_LICENSE |
| Contextual | NAME, ADDRESS, DATE_OF_BIRTH |

The product keeps detecting STUDENT_ID and every other type it has. The corpus
does not plant student IDs. Any prediction outside the eleven types counts as
a false positive in the unrestricted view, as before.

The product rule for DRIVER_LICENSE is an 8-digit number after a licence cue.
Before the generator is frozen, check the number formats printed on Thai
licences against a Department of Land Transport source and record the source
in the corpus manifest. If the product rule misses a real format, that is a
finding to report, not a reason to shape the corpus around the rule.

## Questions and endpoints

Q1. How well does the full system detect the eleven types on documents it was
not developed on?

Primary endpoint: unrestricted entity-level micro F2 of AI Guard on the test
split, with a 95% percentile document-bootstrap interval (1,000 resamples,
seed 0). Also report P, R, F1, per-type rows, the shared-11 view, and the
negative slice (clean documents and false positives).

Q2. Is the hybrid design better than rules alone, NER alone, an LLM, and an
existing PII tool?

For each comparator, the endpoint is the paired micro F2 difference, AI Guard
minus comparator, with a 95% paired document-bootstrap interval over the same
resamples. Five comparisons, Holm-corrected at family alpha 0.05. Report three
views for every system: all eleven types, the structured group, and the
contextual group. The fair comparison for a NER-only system is the contextual
group, because it cannot emit structured labels. The fair comparison for the
regex baseline is the structured group. The all-types view is still printed.

Q3. Does each layer earn its place?

Remove one layer at a time (`fp`, `tb`, `address_merge`) with
`benchmark/blind_v2/ablate.py` and report the paired F2 and recall difference
against the full system. These are interventions, not additive shares.

Secondary, descriptive only: warm p50 and p95 latency per document, peak
resident memory, whether the system runs offline, and cost.

An interval that includes zero is reported as no demonstrated difference.
Null and negative results are reported.

## Systems

| System | What it is |
|---|---|
| aiguard | `predict_ablated(text, None)`, default thainer CRF, frozen commit |
| regex | cue-and-pattern baseline in `benchmark/blind_v2/baselines.py`, extended with a licence pattern |
| crf-ner | PyThaiNLP thainer CRF, mapped tags only |
| wangchanberta-ner | WangchanBERTa NER, mapped tags only |
| presidio | Presidio analyzer, version pinned in the run manifest |
| llm | one local model, named with its digest before scoring |

The LLM runs locally through the existing `benchmark/blind_v2/llm.py` harness,
five seeds, mean and range reported. It must be the largest instruction model
that runs on the owner's machine, and at least a 4B-class model. No hosted API
is called unless the owner approves it in writing first.

Matching uses `benchmark/blind_v2/score.py` unchanged: type-aware overlap, one
gold span matches at most one prediction of the same type. Package versions,
model hashes, the scorer hash, and the git commit go in every run file.

## Corpus

Synthetic only. No real person's data is collected, searched for, or copied.
Public form layouts and wording may be used as templates. Every value is
generated.

| Split | Documents | Use |
|---|---:|---|
| dev | 300 | error inventory and any detector fix |
| test | 800 | scored once |

Targets: at least 150 gold entities per type in the test split, and 20%
negative documents in each split. Negative documents carry look-alike numbers
(order codes, reference numbers, invalid checksums) and no personal data.

Structured values come from a seeded generator and pass their checksum where
one exists (Thai ID mod 11, card Luhn). Document text is written from the
annotation guide and the value pools by an author that does not read detector
code, earlier corpora, or results. A second fresh context reviews labels,
boundaries, and negative purity under fix-only rules. Gold spans come from
construction, never from a detector.

Template families are disjoint between dev and test. A family and all its
variants stay in one split.

At least two model families write the test split if the owner supplies a
second one. If only one family is used, the report says so and claims no
cross-family independence.

## Order of work and isolation

1. Freeze this record, the scheme, and the annotation guide.
2. Build the generator and the dev split.
3. Run the dev split. Fix confirmed mechanisms only, with tests first.
4. Freeze the detector commit and record it here in an addendum.
5. Author and review the test split. Lock it by SHA-256 and encrypt it with the
   existing blinding helper.
6. Score every system and ablation on the test split once.
7. Update CLAIM-MAP, the poster, and the slides.

The detector cannot change between steps 4 and 6. Because the test split does
not exist before step 4, it cannot shape the detector. If a defect forces a
detector change after step 4, the test split is spent and a new one is needed.

## Annotation check

A person who did not write the documents labels a random 10% sample of the
test split from the annotation guide alone. Report entity-level agreement
(Cohen's kappa on token labels and exact-span agreement). If this is not done
before 24 November 2026, the poster states that the corpus is single-annotated
and the check is reported when it is complete.

## What this will and will not support

It supports a claim about these constructed Thai documents, a statistical
comparison between systems on them, and a per-layer account of the design.
It does not support real-document accuracy, legal compliance, anonymity, or
general superiority over the comparators.

The submitted abstract stays as submitted. The poster and slides may show the
v2 result if it is labeled as measured after the abstract, with the abstract's
0.947 kept and labeled as the development set.

## Stopping rules

One scoring run on the test split. No per-document test result, test text, or
intermediate candidate is disclosed before that run. After it, no tuning
against this split. A failed integrity check is a failed evaluation. A new
hypothesis after disclosure needs a new record and a new test split.

## Addendum 2026-11-13: driving licence number format

Searched the same day. No Department of Land Transport page that states the
length of the licence number was found.

- The official card form is in the Royal Gazette, volume 134, special part
  224 Ngor, 13 September 2017. It labels the field "เลขที่ใบอนุญาต". The
  gazette host was not reachable from the build machine, so the form itself
  was not read.
- A commercial Thai licence OCR service returns the licence number and the
  national ID as two separate fields
  (https://docs.aigen.online/docs/api/aiscript/driver-license).
- Another OCR vendor's sample output shows an 8-digit licence number
  (https://iapp.co.th/en/blog/what-is-thai-document-ocr-beginners-guide).
  This is a sample, not a format rule.

Working rule for the generator: an 8-digit licence number, optionally printed
beside the holder's 13-digit national ID, which is labeled THAI_ID. The
8-digit length is UNVERIFIED against a primary source. The owner checks it
against a physical licence (digit count and grouping only, never the value)
before the generator is frozen. The poster must not call the format official
until that check is recorded here.

## Addendum 2026-11-13: resampling unit and corpus shape

Written before any document was generated or scored.

Documents are built from authored templates. One template is a family, and a
family yields several documents that share wording and differ in values. Those
documents are not independent, so every bootstrap in this record resamples
families, not documents (a cluster bootstrap). Intervals are still 95%
percentile intervals from 1,000 resamples with seed 0.

Shape: dev is 100 families with 3 variants each, test is 200 families with 4
variants each. The generator is `benchmark/yrss_v2/corpus.py`, the author
rules are in `docs/research/yrss-eval-v2-annotation-guide.md`, and each split
has a lock file with hashes and counts only.

Scoring needs the eleven-type scheme, so the harness passes the scheme to the
scorer as a parameter. The matching rule in `benchmark/blind_v2/score.py` is
not changed, and its default behavior stays as it is for the older splits.
